What is CI/CD?

Easy⭐ VIBasics▼

📌 Revision keywords

  • CI
  • CD
  • Jenkins
  • TestNG

CI = merge code frequently, automated build+test on each commit. CD = automated deploy to staging/prod with approvals and rollback.

From your experience

Optima Jenkins: Maven build → TestNG → artifact to Nexus → deploy stages per env — ~60% less manual deploy effort.

Follow-ups

Continuous deployment vs delivery? Deployment = auto to prod; delivery = auto to staging, manual prod gate.

Split the terms

CI = merge + build + test on every commit (catch breakage early). CD = Continuous Delivery (always deployable, deploy is a button) or Continuous Deployment (auto-deploy on green). Benefit: small, frequent, low-risk releases with fast feedback.

STAR: Jenkins pipelines — 60% manual effort reduction

Hard⭐ VIJenkins▼

📌 Revision keywords

  • Jenkins
  • SM Tool complemented Jenkins for Fuse

Replaced manual JAR copy/config/restart with standardized pipeline — consistent releases, faster feedback, team freed for features.

Detailed explanation

  • Declarative or scripted pipeline with stages: checkout, build, test, publish, deploy
  • Credentials for SSH/deploy; parameterized env (dev/test/prod)
  • Notifications on failure; smoke test post-deploy (health URL)
  • SM Tool complemented Jenkins for Fuse-specific deploy steps

Example

pipeline {
  stages {
    stage('Build') { steps { sh 'mvn -B clean package' } }
    stage('Test') { steps { sh 'mvn test' } }
    stage('Deploy') { steps { /* promote artifact */ } }
  }
}

Follow-ups

How rollback? Redeploy previous artifact tag from Nexus; blue-green if infra supports.

STAR + proof

S: manual, error-prone deploys. T: automate + speed up releases. A: built Jenkins pipelines (build→test→artifact→deploy→smoke test) with rollback. R: ~60% manual effort cut, fewer release errors. Bridge: faster, safer releases scale directly to ICE's delivery cadence.

Example

ENTRYPOINT ["java","-jar","/app.jar"]

Follow-ups

Don't run as root; set memory limits; healthcheck in Dockerfile or K8s probe.

Best practices

  • Multi-stage build: Maven/Gradle in a builder stage, copy only the jar into a slim JRE/jlink runtime image.
  • Layer wisely (dependencies before app code) for cache reuse.
  • Run as non-root, pin base image versions, scan for CVEs.

Container vs virtual machine — simple comparison

MediumDocker▼

📌 Revision keywords

  • In simple terms:
  • trade-offs
  • VM runs full OS per instance — heavy.
  • Container shares host kernel — lighter, starts in seconds.
  • Both package apps; containers pack more per server.
  • K8s orchestrates containers at scale.

The key difference

A VM virtualizes hardware and ships a full guest OS (heavy, slow boot, strong isolation). A container shares the host kernel and packages just the app + deps (lightweight, fast, denser). Containers = faster scaling/deploys; VMs = stronger isolation/multi-OS.
