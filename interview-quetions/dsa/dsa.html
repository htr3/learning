Recursion vs backtracking — when to use each?

Medium⭐ VIBasics▶ Visual▼

📌 Revision keywords

  • undo
  • ArrayList
  • Recursion needs base case + progress toward it
  • Backtracking = choose → explore → undo
  • Used for subsets, permutations, N-Queens
  • Often exponential — prune early

Recursion

Function calls itself on smaller subproblem — tree height, factorial, merge sort divide step. Needs base case + progress toward base case.

Backtracking

Try choice → recurse → undo choice if path fails. Used for subsets, permutations, N-Queens, maze paths.

Template

void backtrack(int idx, List<Integer> path) {
  if (idx == nums.length) { result.add(new ArrayList<>(path)); return; }
  path.add(nums[idx]);
  backtrack(idx + 1, path);
  path.remove(path.size() - 1); // undo
  backtrack(idx + 1, path);    // skip
}

Complexity

Often exponential — prune early (sort + skip duplicates, bounds check).

The template

Backtracking = choose → explore (recurse) → un-choose (undo). Always define the base case first. Watch recursion depth (deep recursion → StackOverflowError); convert to iteration with an explicit stack if needed.

GCD and prime numbers — interview math basics

EasyMath▶ Visual▼

  • GCD and prime numbers — interview math basics

  • Check prime up to √n

GCD (Euclidean algorithm)

int gcd(int a, int b) {
  while (b != 0) { int t = b; b = a % b; a = t; }
  return a;
}

O(log min(a,b)). LCM(a,b) = a*b / gcd(a,b).

Prime check

Test divisors up to √n — O(√n). Sieve of Eratosthenes for many primes up to N — O(N log log N).

Where it appears

Modular arithmetic, coprime pairs, scheduling problems, cryptography basics.

The classics

Euclid's GCD: gcd(a,b)=gcd(b, a%b) — O(log min(a,b)). Primality up to √n; for "all primes ≤ n" use the Sieve of Eratosthenes — O(n log log n).

Two Sum — HashMap approach

Easy⭐ VIArray▶ Visual▼

📌 Revision keywords

  • HashMap
  • Store value→index while scanning
  • Check if (target − current) already seen
  • O(n) time, O(n) space
  • Sorted array → two pointers instead
  • Store value→index; for each x check if (target − x) seen.
  • O(n) time, O(n) space.
public int[] twoSum(int[] nums, int target) {
  Map<Integer, Integer> seen = new HashMap<>();
  for (int i = 0; i < nums.length; i++) {
    int need = target - nums[i];
    if (seen.containsKey(need)) return new int[] { seen.get(need), i };
    seen.put(nums[i], i);
  }
  return new int[0];
}

Follow-up

Sorted array → two pointers O(n) O(1) space.

The insight

One pass with a HashMap of value→index: for each x, look for target - x. O(n) time, O(n) space — beats the O(n²) brute force. If the array is sorted, two pointers gives O(1) space.

Sliding window — longest substring without repeating characters

Medium⭐ VIArray▶ Visual▼

📌 Revision keywords

  • HashMap
  • Variable window: longest/shortest satisfying condition
  • Fixed window: subarray of size K
  • Track counts in HashMap for duplicates
  • O(n) — each element enters/leaves once

Pattern

Expand right, shrink left when constraint breaks. Fixed window = subarray sum exactly K; variable window = longest/shortest satisfying condition.

int left = 0, best = 0;
Map<Character, Integer> last = new HashMap<>();
for (int right = 0; right < s.length(); right++) {
  char c = s.charAt(right);
  if (last.containsKey(c)) left = Math.max(left, last.get(c) + 1);
  last.put(c, right);
  best = Math.max(best, right - left + 1);
}

O(n) time, O(1) space (charset size bounded).

When to use

Contiguous subarray/substring problems with a constraint (max sum of size k, longest substring without repeats). Expand the right edge, shrink the left when the window breaks the constraint — O(n) instead of O(n²).

Prefix sum — range sum queries & subarray sum equals K

Medium⭐ VIArray▶ Visual▼

📌 Revision keywords

  • HashMap
  • prefix[i] = sum of nums[0..i]
  • Range [l,r] sum = prefix[r] − prefix[l−1]
  • Subarray sum K: count prefixes where (curr−K) seen before

Prefix array

prefix[i] = sum(nums[0..i]). Range sum [l,r] = prefix[r] − prefix[l−1] in O(1) after O(n) preprocess.

Count subarrays with sum K

Running prefix + HashMap count of prefix values seen. If (currSum − K) exists in map, add its frequency.

Map<Long, Integer> freq = new HashMap<>();
freq.put(0L, 1);
long sum = 0, count = 0;
for (int x : nums) {
  sum += x;
  count += freq.getOrDefault(sum - K, 0);
  freq.merge(sum, 1, Integer::sum);
}

O(n) time, O(n) space.

The trick

Precompute cumulative sums once (O(n)); then any range sum is prefix[j+1] - prefix[i] in O(1). Combine with a HashMap of prefix sums to count subarrays summing to k in one pass.

Singly vs doubly vs circular linked list

EasyLinked List▶ Visual▼
  • Singly: one next pointer, can't go backward
  • Doubly: next + prev — O(1) delete at node
  • Circular: last → head — round-robin use cases

📌 Revision keywords

  • LinkedList<E>
  • ListNode { int val; ListNode next; }
  • Singly:
  • Doubly:
  • Circular:
  • Singly: one next pointer — less memory, can't traverse backward
  • Doubly: next + prev — O(1) delete at known node (LRU cache), bidirectional traversal
  • Circular: last node points to head — round-robin schedulers, Josephus problem

Singly (one next pointer), doubly (prev+next — easy backward/delete), circular (tail→head, ring buffers). O(1) insert/delete at a known node, but O(n) random access and poor cache locality vs arrays.

Reverse linked list (iterative)

Medium⭐ VILinked List▶ Visual▼

📌 Revision keywords

  • In simple terms:
  • Reverse linked list (iterative)
  • Three pointers: prev, curr, next
  • curr.next = prev; advance all three
  • O(n) time, O(1) space
  • Three pointers: prev, curr, next.
  • O(n) time, O(1) space.
public ListNode reverse(ListNode head) {
  ListNode prev = null, curr = head;
  while (curr != null) {
    ListNode next = curr.next;
    curr.next = prev;
    prev = curr;
    curr = next;
  }
  return prev;
}

Follow-up

Reverse between positions m and n — find node before m, reverse sublist length (n−m+1).

The iterative pattern

Three pointers (prev, curr, next): save next, point curr.next→prev, advance both. O(n) time, O(1) space. The recursive version is elegant but O(n) stack — mention both.

Cycle detection — Floyd's tortoise and hare

Medium⭐ VILinked List▶ Visual▼

📌 Revision keywords

  • In simple terms:
  • Cycle detection — Floyd&#x27;s tortoise and hare
  • Floyd: slow +1, fast +2 — meet means cycle
  • Find cycle start: reset slow to head, both +1
  • O(n) time, O(1) space

Has cycle?

Slow moves 1, fast moves 2. If they meet → cycle. O(n) time, O(1) space.

Find cycle start

After meeting, reset slow to head; move both 1 step until they meet — that node is cycle entry.

boolean hasCycle(ListNode head) {
  ListNode slow = head, fast = head;
  while (fast != null && fast.next != null) {
    slow = slow.next;
    fast = fast.next.next;
    if (slow == fast) return true;
  }
  return false;
}

Floyd's algorithm

Slow (1 step) + fast (2 steps) pointers; if they meet, there's a cycle. To find the cycle's start, reset one pointer to head and advance both one step until they meet. O(n) time, O(1) space.

Level order traversal (BFS on tree)

Medium⭐ VITree▶ Visual▼

📌 Revision keywords

  • size
  • BFS
  • ArrayList
  • Queue + snapshot size each level
  • Add children after processing node
  • Used for level sums, zigzag, min depth

Queue + process size nodes each level. O(n) time, O(n) space worst (last level).

Queue<TreeNode> q = new LinkedList<>();
q.offer(root);
while (!q.isEmpty()) {
  int size = q.size();
  List<Integer> level = new ArrayList<>();
  for (int i = 0; i < size; i++) {
    TreeNode node = q.poll();
    level.add(node.val);
    if (node.left != null) q.offer(node.left);
    if (node.right != null) q.offer(node.right);
  }
  result.add(level);
}

Level tracking

Use a queue; to process level-by-level, capture queue.size() at the start of each level loop. O(n) time, O(width) space — handy for "level order", "right side view", "zigzag".

Binary Search Tree (BST) — search, insert, validate

Medium⭐ VITree▶ Visual▼

📌 Revision keywords

  • In simple terms:
  • Binary Search Tree (BST) — search, insert, validate
  • Search/insert O(h) — O(log n) if balanced
  • Validate BST: pass min/max bounds, not just parent check
  • Inorder traversal = sorted values
  • Left < root < right at every node.
  • Search/insert O(h) — O(log n) if balanced, O(n) if skewed.

Validate BST

Pass min/max bounds down recursion — not just compare parent.

boolean isValid(TreeNode node, long min, long max) {
  if (node == null) return true;
  if (node.val <= min || node.val >= max) return false;
  return isValid(node.left, min, node.val)
      && isValid(node.right, node.val, max);
}

Complexity caveat

search/insert/delete are O(h): O(log n) only if balanced. A sorted-insert sequence degenerates into a linked list → O(n). Real systems use self-balancing trees (Red-Black/AVL); Java's TreeMap is Red-Black.

Height, depth, and diameter of a binary tree

MediumTree▶ Visual▼
  • Height: max(left, right) + 1
  • Diameter at node: leftHeight + rightHeight
  • Track global max during recursion

📌 Revision keywords

  • Height:
  • Depth of node:
  • Diameter:
  • Height: max edges root to leaf — recursive max(left, right)+1
  • Depth of node: distance from root to that node
  • Diameter: longest path between any two nodes — at each node: leftHeight + rightHeight, track global max

One post-order pass

Compute height bottom-up; at each node the diameter candidate = leftHeight + rightHeight. Track a global max while returning height. O(n) — don't recompute height per node (that's O(n²)).

Lowest Common Ancestor (LCA)

Medium⭐ VITree▶ Visual▼

📌 Revision keywords

  • In simple terms:
  • Lowest Common Ancestor (LCA)
  • BST: walk from root — both left go left, both right go right, else found
  • Binary tree: postorder return p/q/upward
  • O(h) time

BST

Walk from root: if both < root go left; both > root go right; else root is LCA. O(h).

Binary tree

Postorder: if node is p or q return node; left/right recursive; if both non-null current is LCA else return non-null child.

Use the BST property

Walk from the root: if both values < node go left, if both > go right, else this node is the LCA (the split point). O(h) time, O(1) space — much simpler than the general-tree LCA.

Maximum depth of binary tree

int maxDepth(TreeNode root) {
  if (root == null) return 0;

}

O(n) time. DFS recursion depth = tree height — watch stack overflow on skewed million-node tree (rare in interviews).

1 + max(depth(left), depth(right)), base case null → 0. O(n) time, O(h) stack. The iterative version is a BFS counting levels.

Binary search (iterative)

Easy⭐ VISearch▶ Visual▼

📌 Revision keywords

  • In simple terms:
  • Binary search (iterative)
  • lo, hi, mid = lo + (hi-lo)/2

  • Variants: first/last occurrence, rotated array
public int binarySearch(int[] a, int target) {
  int lo = 0, hi = a.length - 1;
  while (lo <= hi) {
    int mid = lo + (hi - lo) / 2;
    if (a[mid] == target) return mid;
    if (a[mid] < target) lo = mid + 1;
    else hi = mid - 1;
  }
  return -1;
}

Follow-ups

First/last position of target — binary search then bias left or right. Search in rotated sorted array.

Pitfalls

Requires sorted input; O(log n). Compute mid as low + (high-low)/2 to avoid integer overflow. Master the variants: first/last occurrence, lower/upper bound, and "search in rotated array".
