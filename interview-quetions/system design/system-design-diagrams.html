Idempotent API — safe retries

Idempotency-Key header + stored response — activation / orders.

sequenceDiagram participant C as Client participant G as Gateway participant S as Service participant DB as Idempotency store C->>G: POST /activate Idempotency-Key: abc-123 G->>S: forward S->>DB: lookup abc-123 alt first request S->>S: process activation S->>DB: store abc-123 + 201 response S-->>C: 201 Created else retry same key DB-->>S: cached 201 body S-->>C: 201 Created (no double charge) end 
POST /activate
Headers: Idempotency-Key: abc-123
Body:    { simId, planId }

First call:
  Service ──► idempotency_keys table: miss
         ──► BSS activate (side effect ONCE)
         ──► INSERT key abc-123, response_hash, status=201
         ──► return 201

Retry (network timeout, client retries same key):
  Service ──► lookup abc-123: HIT
         ──► return stored 201 (NO second BSS call)

Kafka consumer variant:
  messageId in processed_events table — at-least-once + idempotent = exactly-once effect
